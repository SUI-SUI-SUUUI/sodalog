# そだログ

そだログは、LINEから園芸作業の記録を送るだけで、Googleスプレッドシートと Google
Driveに自動整理する園芸記録管理アシスタントです。

## 概要

庭仕事中にパソコンを開かなくても、LINEのリッチメニューから開くLIFF(LINE内で動くWebフォーム)に入力するだけで、日付・場所・植物名・作業内容・写真を記録できます。

記録は「アルバム」タブで振り返れます。まず場所(区画)を選び、次にその場所の植物を選ぶと、時系列のカード一覧(写真つき)が並びます。1画面に写真が大きく2列で並ぶグリッド表示です。

## 解決したい課題

園芸作業の記録は、写真・日付・場所・植物名・作業内容が分散しやすく、あとから振り返りにくいという課題があります。特に、育てている場所が広く植物の種類が多いほど、植物1つ1つを個別に追いかける管理は破綻しやすくなります。

そだログでは、普段使っているLINEを入口にして庭仕事の流れを止めずに記録を残せるようにし、さらに「場所(区画)」を記録の主役に据えることで、広い庭でも振り返りやすい仕組みを目指しています。

## 使い方

### 記録する(LIFFフォーム・正式な導線)

LINEのリッチメニューの「記録する」から、LIFFのWebフォームを開きます。

- 実績があれば、最初に「最近使った場所」が写真カードで並び、タップするとその場所を選んだ状態でフォームに進みます(実績がなければ通常のフォームが開きます)
- 作業日はカレンダーから選択
- 場所・詳細場所・植物名・作業内容・メモを入力し、「内容を確認する」→「LINEへ送信して記録する」
- 保存後、続けてLINEトークへ写真を送ると、その記録に紐づけてGoogle Driveへ保存されます

### アルバムで振り返る(LIFF)

- 「アルバム」タブで、①場所を選ぶ→②その場所の植物を選ぶ→③その場所×植物の記録を時系列カードで見る、という3階層で振り返れます
- 各カードの一覧は写真つきの2列グリッド表示です
- 「相談」タブは準備中です(将来、蓄積した写真・記録を使ったAI診断を構想中)

### LINEにテキストを送って記録する(補助的な導線)

LIFFを使わなくても、次の形式のテキストをLINEに送ると記録できます。

```text
2026/07/13_北側_中央_つつじ_剪定
```

形式:`作業日_場所_詳細場所_植物名_作業内容`

「記録する」と送ると、番号を選びながら段階的に入力する方法も使えます(作業日→育成拠点→場所→詳細場所→植物名→作業内容→メモの順)。入力途中は「中止」でキャンセルできます。

### その他のコマンド

| 送信テキスト | 動作 |
|---|---|
| 記録する / 記録 / 園芸記録 | 番号選択による記録を開始 |
| 使い方 / ヘルプ / メニュー | 操作方法を表示 |
| 中止 / キャンセル | 入力途中の記録を中止 |

## 現在できること

- LINEリッチメニューから開くLIFFフォームでの記録(カレンダー入力、写真添付)
- LIFFの記録フォームに「最近使った場所」の写真カード入口(場所を選ぶだけですぐ記録画面へ)
- LIFFのアルバムタブ:場所→植物の2階層ドリルダウンと、写真つきの時系列カード一覧
- 場所・植物の一覧を、代表写真つきの2列グリッドで表示
- LINEテキスト送信による記録(1行テキスト形式・番号選択形式の両方に対応、後方互換あり)
- Googleスプレッドシートへの記録保存(`garden_log` シート)、記録完了メッセージのLINE返信
- LINEから送信した画像、およびLIFFから保存後に送った画像をGoogle Driveへ保存
- 保存した画像は非公開のまま、認証済みの本人だけがアルバムから閲覧できるプロキシ方式
- 場所 / 詳細場所 / 年ごとのDriveフォルダ自動作成
- LINEリッチメニューの作成・設定(GASから実行)

## 今後の予定

「場所が主役、植物はタグ」という設計への転換を計画中です。詳細は [docs/liff-album-spec.md](docs/liff-album-spec.md) の STEP 8以降を参照してください。概要:

- 記録の入力・振り返りともに「場所(区画)」を主語にし、植物名は任意で複数付けられる「タグ」にする
- 記録操作を最短化する(場所を選ぶ→必要なものだけ入力→保存)
- 将来的に、場所を今の固定選択式からユーザーが自由に登録できる形に変更する
- 月ごとの園芸作業ふりかえり
- LINE Webhookの署名検証に対応できる公開基盤への移行検討(一般公開時)

## システム構成

```text
LIFFフォーム(GitHub Pagesで配信)
  ↓ LINEへ記録を送信
LINE Messaging API
  ↓
Google Apps Script
  ├─ 入力内容をスプレッドシートへ保存
  ├─ 写真をGoogle Driveへ整理
  ├─ アルバム用の記録一覧を返す(認証つき)
  └─ 認証済み利用者へ画像を返す(プロキシ)
```

LIFFのIDトークンをGoogle Apps Scriptで検証し、本人の記録だけを扱います。詳しくは [docs/liff-github-pages.md](docs/liff-github-pages.md)・[docs/liff-album-spec.md](docs/liff-album-spec.md) を参照してください。

## 現在の利用範囲とセキュリティ方針

現在のそだログは、開発者本人のみが利用するMVPです。

LINEから届いたイベント・LIFFからのリクエストの送信元LINEユーザーIDを確認し、Google Apps
Scriptのスクリプトプロパティに登録した本人のLINEユーザーIDと一致する場合だけ、メッセージ処理・画像保存・スプレッドシートへの記録・アルバムの取得を行います。

```text
LINEからのイベント / LIFFからのリクエストを受信
  ↓
送信元のLINEユーザーIDを確認(LIFFはIDトークンをLINEプラットフォームへ問い合わせて検証)
  ├─ 許可された本人 → 処理を実行
  └─ 本人以外       → 処理せず終了
```

許可するユーザーIDは、次のスクリプトプロパティで管理しています。

```text
ALLOWED_LINE_USER_ID
```

アクセストークン、チャンネルシークレット、保存先IDなども、コードへ直接記載せず、Google
Apps Scriptのスクリプトプロパティで管理しています。Driveの写真は共有設定を非公開のままにし、認証済みの本人だけがプロキシ経由で取得できます。

### MVPでの対応範囲

- 開発者本人だけが利用
- 許可されたLINEユーザーIDだけ処理
- 未許可ユーザーからのイベント・リクエストは保存・返信・データ返却をしない
- 秘密情報や保存先IDはスクリプトプロパティで管理
- LINE公式アカウントの追加用URLやQRコードは一般公開しない

### 一般公開時に必要な対応

現在のGoogle Apps Script単体構成では、LINEから送られる
`X-Line-Signature` を公式に案内された方法で検証することが困難です。また、`garden_log`
シートは全利用者分を1枚で持つ設計のため、利用者・記録数が増えるほど検索が遅くなります。

一般公開する場合は、次のような対応を検討します。

```text
LINE
  ↓
Cloud Runなど
  ↓ X-Line-Signatureを検証
Google Apps Script
  ↓
Google Spreadsheet / Google Drive(利用者ごとに分離)
```

- LINE Webhookの受付口にCloud Runなどを追加し、署名検証を完了したイベントだけをバックエンドへ渡す
- 利用者ごとにスプレッドシート/Driveを分離し、全件スキャンをやめる
- アルバムの一覧・集計をサーバー側で計算して返す

この対応は、現在の本人限定MVPには導入せず、一般公開版へ移行する段階で実施します。

## コード構成

Google Apps Script のコードは `gas/` 配下で機能別に分割しています。

| ファイル | 役割 |
|---|---|
| `00_Config.gs` | 定数・シート名・ヘッダー定義 |
| `01_Webhook.gs` | Webhook受信(`doPost` / `doGet`)、テキスト・画像・LIFFリクエストの振り分け |
| `02_RecordFlow.gs` | 番号選択による園芸記録入力フロー(LINEテキストの段階入力) |
| `03_ValidationDate.gs` | 1行テキスト・LIFF送信内容の検証・日付処理 |
| `04_Image.gs` | 画像保存・Driveフォルダ管理 |
| `05_HelpHistory.gs` | 使い方の表示 |
| `06_SheetsSessions.gs` | スプレッドシート操作・ユーザーセッション管理 |
| `07_LineUtilities.gs` | LINE返信・JSON応答・デバッグログ |
| `08_RichMenu.gs` | リッチメニューの作成・設定 |
| `09_Liff.gs` | LIFFのIDトークン検証、LIFF利用者の許可判定 |
| `10_Album.gs` | アルバム一覧取得・画像プロキシ(`action=list` / `action=image`) |
| `99_Tests.gs` | 動作確認用テスト |

LIFFのフロントエンドは `liff/index.html`(1ファイル)で、GitHub Pagesから配信しています。
